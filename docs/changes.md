# Исправления проекта

## Дополнение: просмотр и проверка результатов

- Добавлена автономная панель: выбор выпуска, турбины и горизонта, график, диапазоны, таблица январских метрик и выгрузка выбранных строк CSV.
- `check` сверяет даты и горизонты, всю февральскую сетку, интервалы, итоговые счётчики, таблицу станции и контрольные суммы. Проверка работает непосредственно с ZIP без модели и погодного кэша.
- Публикация CSV использует временный файл с последующей заменой. Итоговый JSON записывается после таблиц и содержит их контрольные суммы.
- `watch` обнаруживает повреждение сохранённых таблиц даже при неизменившейся погоде. `package` проверяет результаты перед упаковкой и добавляет панель в архив.
- Интерфейс разделён на читаемые HTML, CSS и JavaScript; итоговый HTML включает их внутрь и не обращается к внешним библиотекам.
- Добавлены тесты целостности результатов, фильтров и CSV-экспорта, а также [сценарий демонстрации](demo.md).

Визуальное тестирование панели в браузере этой среды было заблокировано политикой доступа к локальным файлам. Проверены генерация HTML, встроенные данные, отсутствие внешних ресурсов, JavaScript-синтаксис и чистые функции фильтрации/экспорта; полноценная браузерная проверка внешнего вида не заявляется.

Ревизия исходного проекта из коммита `f5623d396fa49ff519868f4e2925f2957927fbc6`.

| Проблема | Исправление |
|---|---|
| Час с меткой 23:00 включался в обучение, хотя первый выпуск делался в 23:00 | Все отсечки используют конец часа; исправлены обучение кандидатов, выбор параметров, финальное обучение и базовое среднее |
| Пустой кэш приводил к ошибке до резервного прогноза | Агент выдаёт явно помеченное историческое среднее и диапазон [0,1] |
| Повреждённый файл ломал весь расчёт | В воспроизведении файл изолируется с записью причины, в обучении ошибка остаётся явной |
| Проверялась только одна единица скорости ветра | Проверяются все три переменные для всех трёх давностей, UTC, длина и уникальность временных меток |
| Некорректный ответ мог заменить рабочий кэш | Замена выполняется атомарно после валидации |
| Для каждого частичного запроса создавался отдельный погодный кэш | Один календарный месяц соответствует одному файлу турбины |
| Обучение и прогнозирование по-разному обрабатывали плохую погоду | Общая проверка конечных значений и диапазонов; общий резервный прогноз для оценки и воспроизведения |
| Расчёт нескольких выбранных дней мог перезаписать полный февраль | Отдельные каталоги для одного дня и произвольного диапазона |
| Ежедневный агент ожидал заранее загруженную погоду | Загрузка недостающих месяцев выполняется автоматически; добавлен явный режим без сети |
| Мониторинг пересчитывал неизменившийся прогноз | Сравниваются отпечатки модели, кода, настроек и погодных значений |
| Старую модель можно было использовать после изменения настроек | Версия модели и отпечаток настроек проверяются до расчёта |
| Отчёты и ZIP создавались отдельно от основного запуска | Добавлены `run`, `package`, проверка связи модели с результатами и обновление контрольных сумм |
| Краткие строки кода и длинный README затрудняли чтение | Погодный модуль выделен отдельно, код отформатирован, быстрый запуск отделён от методики |

Проверки: исходные семь тестов сохранены и дополнены регрессионными сценариями. Полный список и результат — [reports/tests.txt](../reports/tests.txt). Модель повторно обучена на двух предоставленных CSV и загруженном погодном архиве; январские метрики и февральские прогнозы пересчитаны.

Ограничения, которые исправлением кода не устраняются: неподтверждённые часовой пояс и смысл меток CSV, отсутствие номинальных мощностей и фактических данных за февраль, отсутствие исторических времён публикации в выбранном погодном API. Они отражены в README и машинных отчётах; строгая проверка доступности погоды не объявляется успешной.
